## 三、v2.1／v2.2 必須更正的實作與說法

### 3.1 基準不能同時要求「同股、同日、同進出時點」又期待非零差

若同一股票、同一開盤買、同一開盤賣、相同成本與部位，報酬必然相同。若出場改用固定時間，則同時改變賣法；若換成同日其他股票，則是在檢驗橫斷面選擇；若換日期，則在檢驗擇時。這三種問題需要分開。

x1／x2 的實際固定基準均為 t+1→t+20，19 個開盤間隔。v2.1 有一處寫成固定 20 根，應以程式定義為準。原 x2 另外對基準要求 t≥199，對訊號沒有同樣門檻；基準只需 t+20 成熟，訊號要求 t+41。上述公平敏感度已統一資格，原池則保留原規則供重現。

### 3.2 成本必須兩邊一起扣

對相同一買一賣、每邊比例成本 c，`淨報酬=(1+毛報酬)×(1−c)/(1+c)−1`。因此兩組均值差只會乘上同一正數 `(1−c)/(1+c)`，不會因對稱成本自己翻轉符號。v2.1「只扣訊號後超額轉負」不是公平的成本比較。

若策略交易次數、每邊費率、成交衝擊、持有資金成本不同，當然可能改變增量；必須實際建模，不能用這個相同成本的例子概括。

### 3.3 「強」不是前一天就完整知道

現行 `regime` 只有 GEX 使用前一交易日；廣度和 HYG／IEF 使用訊號當日收盤。因此可檢驗的流程是 **t 日收盤後計算 sc[t] 及訊號[t]，確認資料可用後，最早 t+1 開盤交易**。

改成 sc[t−1]、或「當天或隔天出現底／回」，都會改規則，須另外登記。也不能把已 lag1 的 GEX 再滯後一次而宣稱沿用原規則。

GEX 來自 SqueezeMetrics 歷史資料，是依模型假設推估的市況資訊，不是直接看見全部機構／做市商部位。歷史廣度以目前擴大名單往回重建，還有存活者偏誤。訊號生成時間、歷史值可取得時間、後續修訂都要留存；「程式有 lag」不能單獨證明當時可得。

### 3.4 345 名單的獨立性須重新認定

固定版本的第 6 輪 `p6_prereg.md` 與 `r6_factors.py`，已明列擴大三來源加原追蹤名單，從 20 個因子、兩方向、兩期間、四分組挑出 F6／F9／F15；`r6_result.json` 報 604 檔、含 602 個股。原 345 ticker 都落在這次固定三來源設計範圍內。

## 五、部位、重複試驗與文章的界線

### 5.1 p05 不能換算成保證最多賠 1–2%

p05 是第5百分位附近的門檻，不是最壞損失，也不是最差5%的平均。以1%÷17.1%=5.85%持倉，只代表歷史p05情境下約損失1%；若標的跌50%，帳戶會損失約2.92%。要叫「風險預算情境」，並加入跳空、尾部平均、產業集中與多檔同時下跌。

兩倍 ETF 多日報酬也不能直接乘二。例如標的先+10%、再−9%，合計+0.1%；理想每日兩倍則先+20%、再−18%，合計−1.6%。SEC 同樣說明每日重設會使多日結果偏離倍數。[SEC 官方公告](https://www.investor.gov/introduction-investing/general-resources/news-alerts/alerts-bulletins/investor-alerts/sec)

### 5.2 DSR >0 不是有效門檻；試驗帳不等於完整修正

DSR 原定義是機率型統計量，不是把超額報酬打折後看是否大於零。若選它，須固定例如95%門檻、報酬序列、有效試驗數及相依估計；直接檢驗平均超額時，也可事前選相應的多重檢定方法。[Bailey／López de Prado 原文](https://www.davidhbailey.com/dhbpapers/deflated-sharpe.pdf)

本輪已建立 `trials_ledger.md`，把可查證的研究家族與本次敏感度分開；2026-10-10 起未完整回填的歷史明列缺漏，**不提供偽造的總試驗數或 DSR**。126日區塊、2,000次重抽不能創造新危機；34段恐慌也不等於34個獨立事件。

最近60筆、連兩季下降一半可以作營運提示，但未驗證為可靠失效檢定。多筆可能發生同一天，前期均值接近0時「少一半」也不穩定；先監測、報不確定性，不自動宣稱市場優勢消失。

### 5.3 附文的方向可參考，不能把所有推論當成實證

機器學習有樣本外預測能力、公開異常可能衰減，相關原文確實存在；但它們不證明「AI 已消滅所有大型股機會」，也沒有證明這套儀表板能比其他散戶早幾天而獲得超額。偵測資金活動仍須證明其對後續報酬有增量。

Gu／Kelly／Xiu、McLean／Pontiff、Chen／Welch（2026）的來源與數字界線、DSR、槓桿及停損資料已逐項查核，見附錄五。未核實的 Medallion／XIV 等枝節沒有拿來建立門檻。

def bootstrap(daily, draws=DRAWS, block=BLOCK, seed=SEED):
    a=np.asarray(daily,dtype=float); n=len(a)
    if n<block: raise ValueError('calendar shorter than block')
    pref=np.vstack([np.zeros(a.shape[1]),np.cumsum(a,axis=0)])
    rng=np.random.default_rng(seed); samples=[]
    for _ in range(draws):
        total=np.zeros(a.shape[1]); remain=n
        while remain:
            length=min(block,remain); start=int(rng.integers(0,n-block+1))
            total+=pref[start+length]-pref[start]; remain-=length
        samples.append(estimates(total))
    samples=np.asarray(samples)
    names=['legacy_pooled_b0_minus_fixed19_all','fixed19_same_date_non_signal_date_equal',
           'fixed19_same_date_non_signal_signal_weighted','same_b0_rule_same_date_non_signal_date_equal']
    point=estimates(a.sum(axis=0)); out={}
    for j,name in enumerate(names):

        out[name]={'mean':float(point[j]),'ci95':np.quantile(v,[.025,.975]).tolist() if len(v) else None,'validDraws':len(v)}

def ratios(z):
    def div(a, b):
        return a / b if b > 0 else np.nan
    return (div(z[1], z[0]) - div(z[3], z[2]),
            div(z[5], z[4]), div(z[7], z[6]), div(z[9], z[8]))


def replay(daily_path, result_path, tolerance=1e-12):
    raw_daily = daily_path.read_bytes()
    raw_result = result_path.read_bytes()
    rows = json.loads(raw_daily)
    expected = json.loads(raw_result)
    by_date = {row['date']: row for row in rows}
    if len(by_date) != len(rows):
        raise ValueError('Daily aggregate file contains duplicate dates')
    dates = sorted(by_date)
    if len(dates) != expected['calendarN']:
        raise ValueError('Daily aggregates do not cover the reported full calendar')
    meta = expected['bootstrap']
    block, draws, seed = meta['block'], meta['draws'], meta['seed']
    if meta['rng'] != 'numpy.default_rng' or not meta['zeroDaysRetained']:
        raise ValueError('Unsupported RNG/calendar convention')
    if not 0 < block <= len(dates) or draws <= 0:
        raise ValueError('Invalid bootstrap parameters')
    alpha = (1 - meta['interval']) / 2
    max_difference = 0.0
    comparisons = 0
    detail = {}
    for state in ('strong', 'other'):
        values = np.zeros((len(dates), 10))
        for i, date in enumerate(dates):
            row = by_date[date]
            if row['state'] not in ('strong', 'other'):
                raise ValueError('Unknown regime label')
            if row['state'] == state:
                agg = np.asarray(row['aggregate'], dtype=float)
                if agg.shape != (10,) or not np.isfinite(agg).all():
                    raise ValueError('Invalid daily aggregate vector')
                values[i] = agg
        point = ratios(values.sum(axis=0))
        rng = np.random.default_rng(seed)
        distribution = []
        for _ in range(draws):
            sampled_dates = []
            while len(sampled_dates) < len(dates):
                start = int(rng.integers(0, len(dates) - block + 1))
                take = min(block, len(dates) - len(sampled_dates))
                sampled_dates.extend(range(start, start + take))
            distribution.append(ratios(values[sampled_dates].sum(axis=0)))
        distribution = np.asarray(distribution)
        detail[state] = {}
        for j, name in enumerate(NAMES):
            ref = expected['results'][state]['bootstrap'][name]
            finite = distribution[:, j][np.isfinite(distribution[:, j])]
            if len(finite) != ref['validDraws']:
                raise AssertionError(f'Valid-draw count differs: {state}/{name}')
            interval = np.quantile(finite, [alpha, 1-alpha]) if len(finite) else None
            if interval is None or ref['ci95'] is None:
                raise ValueError('Empty bootstrap distribution requires explicit review')
            differences = np.abs(np.asarray([point[j], *interval]) -
                                    np.asarray([ref['mean'], *ref['ci95']]))
            if not np.isfinite(differences).all() or (differences > tolerance).any():
                raise AssertionError(f'Estimate/interval differs: {state}/{name}')
            max_difference = max(max_difference, float(differences.max()))
            comparisons += 4  # point, lower, upper, and valid-draw count
            detail[state][name] = {'mean': point[j], 'ci95': interval.tolist(),
                                  'validDraws': len(finite)}
    return {'status': 'PASS_AGGREGATE_CONSISTENCY_ONLY',
            'scope': 'No raw-price, signal, point-in-time, or alpha validation.',
            'calendarN': len(dates), 'comparisons': comparisons,
            'maxAbsoluteDifference': max_difference, 'tolerance': tolerance,
            'numpyVersion': np.__version__,
            'dailySha256': hashlib.sha256(raw_daily).hexdigest(),
            'resultsSha256': hashlib.sha256(raw_result).hexdigest(),
            'replayed': detail}


if __name__ == '__main__':
    parser = argparse.ArgumentParser(description=__doc__)
    parser.add_argument('--daily', type=Path, default=HERE/'audit-output/daily-aggregates.json')
    parser.add_argument('--results', type=Path, default=HERE/'audit-output/audit-results.json')

#### 二、x1 和 x2 實際做了什麼

##### 2.1 x1 的持有期是 19，不是 20

[x1 原始程式](https://github.com/groupuie/market-flow-dashboard/blob/0192eeb094239841305a5e32bcbd8413fb8e1bfb/research/expectancy_2026-10-14/x1_expectancy_vs_baseline.py#L18) 第 18、26、28 行使用 `h=20`，計算 `O[t+20]/O[t+1]-1`，輸出名稱 `hold19`。從 t+1 開盤到 t+20 開盤，是 19 個開盤間隔。v2.1「基準固定 20 根」的註解不精確。

但「19 根」並不等於真的配對平均持有時間：x1 公開結果的 ALL／B0 平均持有為 A 段 19.7698、B 段 19.2466；A 段若真照 v2.1 所提「各段平均四捨五入」，會是 20。更重要的是，固定平均時長不能消除每筆不同持有期、持有期與報酬相關的影響。

x1 基準將股票與所有日期直接合併；B0 則是出現訊號的交易加權。股票歷史較長、訊號較多或某些行情年份較密集，權重都可能不同。因此原來的 ALL 超額約 +0.0154／+0.0616 個百分點，只是這兩個混合分布的差，不能據此判定買點等同隨機。

此外，x1 B0 數字是匯入 v0.5.0 的 `results.json`，並非重新以網站四捨五入訊號重算；x2 才明確重新以四捨五入的價格呼叫現行 `sw_series`。兩者不應標成完全相同的訊號樣本。

##### 2.2 x2 的「同一天」只有同一類市場狀態

[x2 原始程式](https://github.com/groupuie/market-flow-dashboard/blob/0192eeb094239841305a5e32bcbd8413fb8e1bfb/research/expectancy_2026-10-14/x2_strong_vs_baseline.py#L15) 第 15–27 行的實際定義：

| 項目 | 訊號組 | 基準組 |
|---|---|---|
| 股票 | 名單 266 檔，當日有底／回才加入 | 同一名單，每個合格股票日都加入 |
| 日期 | 2021-03-17 至 2026-07-31，且有訊號 | 同期間所有合格日期 |
| 分類 | `sc[訊號日] >= 2` 或其他 | `sc[候選日] >= 2` 或其他 |
| 出場 | 第一個頂隔日開盤；沒有則 t+41 開盤 | 固定 t+20 開盤 |
| 成本 | 0 | 0 |
| 最小歷史 | 訊號迴圈沒有共同 `t >= 199` 門檻；底可更早出現 | 明確從 `t=199` 起 |
| 成熟要求 | 至少有 t+41 | 只要求有 t+20 |
| 加權 | 每個訊號各一筆 | 每個股票日各一筆 |

程式沒有先為每個訊號找同股、同日的控制交易，沒有用該訊號持有時間套到控制組，也沒有以訊號日期的分布重加權所有股票。因此 +1.5605 點不能直接解讀為「同一天選到 Astra 股票多賺 1.5605 點」。

同股、同日、同成交時點與同出場時點若全都相同，兩者報酬必然相同；要研究進場價值，就必須明確改變股票選擇或入場日期其中之一。適合區分的問題為：

- **同日選股**：固定訊號日、固定持有期，比訊號股票與當日合格股票控制組；保持日期權重一致。這是「這天買哪些股」的問題。
- **同股擇時**：固定股票權重與持有期，比訊號日期與事先規定的合格控制日期。這是「這檔哪天買」的問題。
- **賣法增量**：相同股票、相同入場日及本金，比 B0 與 E1 的完整現金流。這是「已經買了如何出場」的問題。

三者可以都報，但不能用一個混合差值同時宣稱三種能力。新的比較都要先統一 IPO 暖機、可交易性、成熟窗口、排除條件與重疊交易處理。

##### 2.3 同成本必須兩邊一起扣

v2.1「訊號扣 10 bp 後，超額轉負」若基準仍是未扣成本，並不符合其提案的對稱成本定義。設每邊成本為 c，一筆全進全出的淨報酬為：

`r_net = (1 + r_gross) × (1-c)/(1+c) − 1`

若訊號與基準都有相同的一進一出，兩邊差為：

`Δ_net = Δ_gross × (1-c)/(1+c)`

因此相同固定比例成本會縮小差距，**不會單獨改變差距正負號**。這不代表真實成本無關；不同流動性、滑價、換手率與多次分批成交仍可能產生非對稱影響。

用 x2 已公布的混合平均、每邊 c=0.001 作純代數換算：

| 分類 | 原混合毛差 | 對稱成本後混合差 |
|---|---:|---:|
| 強日 | +1.560470 點 | +1.557352 點 |
| 其他日 | −0.152013 點 | −0.151710 點 |

這些數字**不是公平基準重算或新的通過證據**；只是指出成本不應只加在訊號一邊。

- 信用：**t 日** HYG／IEF 還原收盤比值，與包含 t 日的最近 60 根最低值比；第 354–361 行。
- 總分：同一天三項加總；第 362 行。

故現行可執行時間順序是「t 日收盤後形成底／回與 sc[t]，最早 t+1 開盤執行」。若改成「sc[t−1] 成立時 t 日或隔日的訊號」，那是另一個規則。v2.2 的「當天或隔天」必須拿掉歧義，不能一邊宣稱沿用原規則、一邊多加一天可選窗口。

##### 3.2 GEX 是供應商推估，非機構逐戶部位真值

第 429 行讀 [SqueezeMetrics DIX.csv](https://squeezemetrics.com/monitor/static/DIX.csv)，取其中 `gex` 欄。供應商將它描述為選擇權造市商的避險義務衡量；其白皮書的計算含有造市商通常持有 call／put 哪一側的假設。因此研究應稱「供應商 GEX 代理」或「推估的 gamma 狀態」，不能寫成已觀察到所有造市商的真實淨部位。[官方指標說明](https://squeezemetrics.com/monitor/dix)、[官方 GEX 白皮書](https://squeezemetrics.com/download/white_paper.pdf)。

此次固定 `meta.json` 記錄 `gen=2026-10-14T01:24Z`、GEX 檔最後日期 2026-10-13；`regime.json` 本身行情截止 2026-10-12。這是**這次回建輸出的時間與資料日期**，不是每一個歷史 GEX 值當年的實際發布時間。未見逐列 `available_at`、供應商原始回覆雜湊、每日歷史版本或精確 HTTP 下載時刻。

使用 t−1 確實比使用 t 日 GEX 保守，但單靠 shift 不能證明所有原始值在 t 收盤前已發布、未經事後修訂。當前資料只能支持回建研究；若要宣稱能當時交易，仍需可得時間佐證或前瞻保存。

##### 3.3 前填、缺值與公布時點

`ffill_on` 第 309–316 行將數列與交易日曆的日期聯集排序，最多前填 **5 個聯集日期位置**；通常近似五個交易日，但不是固定五個曆日。GEX 第 333 行先前填，再延遲一天；HYG、IEF 第 354 行各自前填後再相除。

若某因子缺值，第 362 行只檢查 `==1`，缺值在總分中算 0；第 437 行 GEX 下載失敗也只記警告。因此資料失效可能把原本未知的強日壓成其他日。正式建議級應另外檢查資料完整與新鮮度，未知不能直接視為「條件不成立」。

此次固定快照 2021-03-17 至 2026-07-31 的 1,350 天中，g／b／c 都非 null，sc 也全部等於三項加總；所以**沒有證據說這次 106 個強日被 null 判錯**。但輸出沒有前填的來源日期或 age，不能由「非 null」反推「當日都新鮮」。

##### 3.3 報酬、成本、日內控制池與權重

以訊號收盤日為 t，所有股票在共同日曆 t+1 開盤入場，t+21 開盤出場；兩個開盤相隔 20 個交易日。與「第 20 根開盤」不同，索引測試必須明確。

初始資金 1，每次成交按成交額扣 c=0.001：

```text
r_net(i,t) = O(i,t+21) / O(i,t+1) × (1-c)/(1+c) − 1
```

訊號組 S_t = 當日合格且有底／回的股票；控制組 C_t = 同日合格但沒有底／回的股票。每個組內等權；控制組排除訊號股，避免把同一筆同時算在訊號與基準。若想問「不篩選直接買全部」可另報全母體等權基準，但它會包含訊號股，不能悄悄替代主控制組。

```text
I_t = 1 if 強日、資訊時序合格、S_t非空且C_t非空 else 0
D_t = mean(r_net[i,t] for i in S_t) − mean(r_net[i,t] for i in C_t)
theta = sum(I_t × D_t) / sum(I_t)
```

主估計採**日期等權**，讓同一天的幾十檔訊號不被當成幾十次獨立市場經驗。它回答「典型有訊號的強日」選股差；不是「隨機抽一筆標記」的交易等權均值。交易等權結果、原始訊號與控制均值另報；兩者分歧時必須解釋，不能取較好者。沒有訊號或沒有控制的日子仍保留在完整日曆，I_t=0；D_t 儲存 null，聚合時分子明確為零，不能把缺值變成已完成零報酬交易。

同樣一買一賣、相同費率時，兩組差值只是毛差值乘 `(1-c)/(1+c)`，正負號不會僅因公平扣同樣成本而反轉。只扣訊號組、保留毛基準的比較不公平。仍要同時報訊號策略本身扣成本的絕對平均：相對少虧不等於持倉獲利。若將來費用依流動性不同，需另固定差異成本模型與交易實作。

##### 3.4 推論、分段與資格判斷

- 唯一主統計量是 theta，唯一主區間為完整日曆的 non-circular moving-block bootstrap，區塊長 126 交易日、2,000 次、seed 20261014。每次從完整日曆等機率抽區塊起點，串接至原長度後截斷；同一天整組股票與 I_t／D_t 一起抽，不抽獨立交易，也不先刪掉無訊號日期。

##### 3.5 同日比較消除了什麼、還沒消除什麼

同日進出控制了共同的市場路徑與持有期，沒有自動控制產業、beta、規模、流動性、波動、近期跌幅及股票身分。底／回若選到高 beta 股票，恐慌後反彈較大可能是風險暴露，不宜直接稱「無風險超額」或機構選股能力。

預先指定的描述檢查可用：信號前 252 日、至少 200 個有效觀測估計 beta；按固定產業分類與 beta 組呈現組間不平衡；按產業內配對／分層呈現均值差。產業標籤的歷史有效時間不明時也標明。這些不得用於事後挑贏家，不能在原主檢驗失敗時換成較佳分層作通過。若要把風險匹配設成主題，應在首次看新結果前另定完整控制分層及稀疏群處理，替換本草案，而不是事後追加。

**345 檔換股仍共用已看過的市場日期與 regime，而且可能已直接參與第六輪的因素篩選。** 沒有 §3.0 的隔離證據，連「只降低股票清單重用」也不能保證；即使查明部分股票沒被使用，也無法驗證恐慌擇時條件對新危機的泛化。完整採用需要之後未看過的日期、事前封存的訊號與可用資料快照；本輪不預設任何新回測通過就可直接上線。

#### 5. 試驗帳：可追溯，但不能假裝已完整修正過擬合

每一筆帳記錄：時間、假設家族、規則／參數／樣本／門檻 hash、資料與程式 hash、這次改了什麼、開始計算時間、看過哪些既有結果、主或描述、結果檔、無效／修復原因。回填項目以 `retrospective` 標記，未知次數寫未知；日期不倒填成真正事前登記。

「DSR >0」不能作成功標準。原 DSR 是概率型顯著性統計，包含嘗試次數、試驗 Sharpe 分布／獨立性、樣本長度與報酬形狀；不是把超額平均除以試驗次數，也不是有 ledger 行數就已完成。若要用需先定對應時序報酬、獨立／有效試驗估計與置信門檻，不能把重疊交易均值直接當每日策略報酬輸入。[Bailey、López de Prado 原論文](https://www.davidhbailey.com/dhbpapers/deflated-sharpe.pdf)

本輪建議實作一個可審計的主假設，其餘固定描述。歷史搜尋不完整仍明說；不能宣稱本輪只有一個主題就抹去前面選出「強日」的搜尋成本。若之後讓多個候選都可升級，須先凍結該假設家族與校正方案。新日期封存驗證比虛構完整 DSR 更誠實。

#### 6. 標記狀態與健康度

網站設計建議至少分三態，字樣不能混用：

1. **候選／證據不足**：沒有合格對照、區間跨零、資料可得性未核實、有效日期不足。可保留灰色資訊標記，文字為「尚未證實有超額」。
2. **負向證據**：在事先固定樣本與檢驗下，增量的區間上界仍低於零；寫出期間與基準。點估計負但區間未算，不能用「已證明無效」。若只是低於另行預設的最低經濟效果，另寫「未達實用門檻」，不要誤稱報酬負向。沒有通過不等於有負向證據。
3. **通過該範圍驗證**：具備完整定義、資料時序、推論和未接觸樣本要求，並註明該版本／期間／基準。標記顯示的是規則族群的歷史估計與區間，不是當前單筆交易保證。

每季最近 60 筆／較去年衰退一半可作提醒候選，但同一恐慌日幾十檔可能很快湊滿 60 筆，不能稱足夠新證據；前一年均值接近零或為負時，「少一半」也失去一致含意。先報新增獨立日期、事件段數、成熟樣本、配對平均與區間，資料不足顯示「待觀察」。健康度若會觸發策略停用與恢復，本身是新政策，需固定觸發、最少日期、復核與恢復條件，而非看完圖才決定。

#### 7. 部位上限：可算情境，不可稱保證最大損失

把總資產風險預算 q 除以估計損失比例 L，可以得到 `w=q/L` 的情境部位。例如以歷史 p05 損失 17% 作 L、q=1%，得到約 5.9% 部位；其意義是「若損失為 17% 時，帳戶約損失 1%」，不是「最多只虧 1%」。p05 之外仍有約 5% 的歷史觀察更差，也有抽樣與分布變化風險；多股同時受市場衝擊時，單筆預算會疊加。

止損亦非硬上限：市價止損在跳空或劇烈波動時可能以明顯較差價格成交，限價止損則可能無法成交。應用情境計算、壓力損失與總組合集中度，不能把它包裝成保證最大虧損。[FINRA 官方說明](https://www.finra.org/investors/insights/stop-orders-factors-consider-during-volatile-markets)

兩倍 ETF 的多日損失不能把正股 p05 直接乘 2；每日重設、複利路徑及費用會讓多日結果偏離兩倍。必須用該 ETF 的實際歷史或明確日重設模型另外驗證，不替這輪 1 倍普通股結果背書。[SEC 投資人公告](https://www.investor.gov/introduction-investing/general-resources/news-alerts/alerts-bulletins/investor-alerts/sec)

#### 一、改看扣成本的超額期望值合理，但不能寫「永遠大於零」

`期望值 = 勝率 × 平均獲利 − 敗率 × 平均虧損絕對值` 是把報酬分組後的算術恆等式；若有零報酬交易，應保留其機率而不是把敗率一律當成 `1−勝率` 再計入非零虧損平均。各項須使用同一成本、同一投入本金及相同交易單位。

**本案推論：**樣本平均為正、條件期望為正、長期帳戶成長為正，是三件事。正算術平均不能單獨保證複利成長。簡單反例：兩次報酬 +60%、−50%，算術平均 +5%，但全額連續投入由 1 變成 `1.6×0.5=0.8`，兩次合計 −20%。因此除了每筆均值，還要重播可執行部位的每日淨值、成本、重疊持倉、現金及回撤；不能把許多重疊個股事件當成同一帳戶可以全額依次投入。

「每個建議標記」最多能表示**該類條件在指定資料與規格下有樣本外證據**，不是對每筆交易、每個股票、每種未來市況作保證。賺賠比 ≥1 可以是另訂的風險偏好，但並非正期望值的必要條件：勝率 80%、賺賠比 0.5，若平均虧損為 1，期望仍是 `0.8×0.5−0.2×1=0.2`。反過來，賺賠比高也不必然賺錢。

#### 二、DSR 的門檻不能是「>0」

Bailey 與 López de Prado 的原始 DSR 是把 Probabilistic Sharpe Ratio 的比較門檻提高到多次搜尋下可能出現的最高 Sharpe；其數值是 0–1 的機率型統計量。原論文範例用 95% 作決策門檻，並要求樣本長度、偏度、峰度、試驗 Sharpe 的變異及有效獨立試驗數。因此 **DSR >0 幾乎沒有篩選意義**；若採用它，必須先指定例如 `DSR ≥0.95` 及精確估計方法。[原論文，式 2 與數值範例](https://www.davidhbailey.com/dhbpapers/deflated-sharpe.pdf)

**本案推論／建議：**

- DSR 不是「超額期望值減掉幾成」，也不是看到 0.95 就能宣稱未來有 95% 機率會賺；它依賴估計、搜尋集合及模型假設。
- `trials_ledger.md` 必須包含失敗、被捨棄、不同門檻、不同基準、不同期間與分組的試驗。只有行數不夠計算 DSR：還需要各版本可比較的報酬序列及試驗間相關性；缺失的歷史試驗不能假裝為零。
- 本案主要統計量若是「條件訊號減基準的平均超額」，可以選直接針對此統計量的多重檢定法。Romano–Wolf 原論文處理多個策略對共同基準，透過重抽保留統計量相依並控制整族錯誤率；不是任意扣一個 Sharpe 折扣。[Romano–Wolf 2005](https://onlinelibrary.wiley.com/doi/10.1111/j.1468-0262.2005.00615.x)
- 採哪一種修正、哪些候選算同一個家族、主假設和探索假設的分界，都要在讀新結果前固定。任何修正都不能把已看過的資料變成真正未見資料。

#### 三、126 日區塊可處理相依的一部分，但 2,000 次重抽不是 2,000 次危機

區塊 bootstrap 的目的，是保留序列相依；區塊長度影響有限樣本偏差與變異，並不是越長越保守或有一個普遍正確的固定值。Politis–White 的研究正是討論相依 bootstrap 的區塊選擇及其有限樣本表現。[作者原稿](https://mathweb.ucsd.edu/~politis/SBblock-revER.pdf)

**以下是對 v2.2 已報數量的設計診斷，不是重算結果：**

- 1,350 個交易日除以 126 約為 10.7 個區塊長度；這是資訊量的粗略提醒，**不是精確有效樣本數公式**。106 個強日、34 段恐慌也不代表 34 個彼此獨立的事件。
- 2,193 筆股票訊號共用市場、產業及重疊持有日。應以完整市場日曆抽區塊，同一天所有股票、訊號與基準一起搬動；不可逐筆獨立抽樣，也不可先只留下 106 個強日再把它們當連續交易日。
- 若主估計量是每筆訊號加權均值，應重抽每天的超額報酬總和與事件數，再算兩者的比；先算每日平均再等權平均，是另一個估計量，不能混稱。
- 2,000 次重抽只減少重抽演算法的隨機誤差，不增加新的危機或新的景氣周期。事前可以固定 63／126／252 日敏感度與逐年、去掉最大恐慌段等診斷，但不得依結果挑有利區塊。
- 換 345 檔股票有助檢查橫斷面外推，卻仍共用同一批 2021–2026 市場狀態。如果「強日」門檻是從那些危機挑出的，換股票不會消除狀態選擇的時間洩漏。應稱為「同歷史市況的新股票確認」，再保留凍結後的新日期驗證。
- 「其他日有 18,624 筆，幾乎確定不是正的」不能由筆數與 −0.15 點的樣本平均推出。相依、持有期及基準偏誤都可能主導不確定性；應寫「目前點估計未見超額」，待正確區間後再判定。

#### 四、槓桿 ETF 與 p05 不能用來保證最大虧損

SEC 說明大多數槓桿 ETF 追蹤的是**單日**倍數，持有多日會受到每日重設與複利影響；其官方案例甚至有指數四個月上漲 2%、對應 2 倍 ETF 卻下跌 6%。所以附文的「兩倍不會改變期望值正負」及 v2.2 的「最差 5% 直接乘 2」不能套用到數週的 ETF 交易。[SEC 官方投資人公告](https://www.investor.gov/introduction-investing/general-resources/news-alerts/alerts-bulletins/investor-alerts/sec)

**本案算術與規格建議：**

1. `p05=−17.1%` 是樣本第 5 百分位附近的報酬門檻，不是最差虧損上限，也不是最差 5% 交易的平均（後者是尾部平均概念）。未來尾端還可能更差。
2. 若以 `1% ÷17.1%=5.85%` 得出持倉，只能寫「以歷史 p05 作情境尺度的部位」。若實際跌 50%，該部位損失約為總資產 2.92%，已超過 1%；不能叫「單筆最多只賠 1%」。
3. 停損價格也不是保證成交價格。FINRA 指出，停損單觸發後成為市價單，劇烈行情時成交價可能明顯偏離觸發價；停損限價單則有不成交風險。[FINRA Regulatory Notice 21-12](https://www.finra.org/sites/default/files/2021-03/Regulatory-Notice-21-12.pdf)
4. 部位欄位可先報「風險預算情境」，同時放入跳空壓力、共同市場下多檔持倉、產業集中及整體槓桿。兩倍 ETF 要直接使用 ETF 的真實日資料／可交易路徑及費用，或另行明確標示理想化每日重設模擬，不能把普通股整筆報酬乘二。
5. 若只有買賣現股且不借款，將該部位歸零列為最嚴重單部位情境，比把歷史 p05 稱作最大損失誠實；這不是建議把全部持倉都壓到同一個固定百分比，而是把「情境」與「上限」分清楚。

#### 五、三篇市場效率文獻：哪些數字核實，哪些推論過頭

##### 5.1 Gu、Kelly、Xiu（2020）：有樣本外預測增量，不是「AI 必勝」或「AI 無用」

原文確認約 3 萬檔股票、1957–2016、94 個個股特徵與總體交互作用等超過 900 個基礎訊號；股票層級樣本外月報酬 R² 約 0.33–0.40%，神經網路多空組合年化 Sharpe 1.35（市值加權）、2.45（等權）。但組合層級的 S&P 500 預測 R² 可達約 1.08–1.80%，所以「所有 ML 預測 R² 都不到 1%」概括過頭。本文不是 Astra 訊號，也不是在檢驗 AI 普及導致效率提高的因果效果。[RFS 原文](https://academic.oup.com/rfs/article/33/5/2223/5758276)

##### 5.2 McLean、Pontiff（2016）：發表後衰減有證據，不等於所有優勢必然歸零

原始摘要核實：97 個預測變數，樣本外平均報酬比原樣本低 26%，發表後低 58%，兩者差 32 個百分點被作者用來估計與發表資訊交易相關的衰減。這不是每條規則固定折價 58%，也不是 AI 的因果識別。附文的「三年 25%、五年 40%」本輪沒有逐表重算，**不採作已核實的精確結論**。[Journal of Finance 原文](https://onlinelibrary.wiley.com/doi/full/10.1111/jofi.12365)

##### 5.3 Chen、Welch（2026）：論文確實存在，48／19／7 bp 也存在，但研究範圍有限

`arXiv:2607.06502` 確實是 Andrew Y. Chen 與 Ivo Welch 的《What Useful Alphas?》。原文摘要的月多空報酬中位數依序有 48 bp（較早期全股票）、19 bp（2006 年起全股票）、7 bp（2006 年起且排除微型股的指定股票集合）。這是約 200 個已發表異常的結果，並非所有大型股交易策略、所有資訊或 AI 方法的定理；論文尚標示工作稿及目標期刊，不能寫成已通過同儕審查。[arXiv v1 全文](https://arxiv.org/html/2607.06502v1)

版本細節：arXiv 條目列 v1 提交於 2026-07-07，所讀 HTML 首頁又標 Draft: August 24, 2026。這兩個日期應原樣記錄，不能把 HTML 的全文內容宣稱為已核實的 7 月當時快照。[arXiv 條目](https://arxiv.org/abs/2607.06502)

##### 5.4 López de Prado 的白皮書：方法警示，不是失敗率的普遍因果估計

GARP 官方確有 2018 年《The 10 Reasons Most Machine Learning Funds Fail》，文中把作者經驗整理為常見失敗原因。它適合支持重視過擬合、流程與風險，但不能單憑題名推出「大部分基金失敗的唯一原因是過擬合」。本輪沒有核驗附文中 Medallion 的 50.75% 命中率、XIV／LJM 細部數字，亦不把它們作為本案門檻。[GARP 原始白皮書](https://www.garp.org/hubfs/Whitepapers/a1Z1W0000054x6lUAA.pdf)
