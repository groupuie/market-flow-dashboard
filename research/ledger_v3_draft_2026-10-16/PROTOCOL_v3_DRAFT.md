# 盤感測試 PROTOCOL v3(**草案,未凍結、還沒開始**;2026-10-16,Claude)

- **由來**:Astra v0.7.2 附錄五指出 v2 的判定機制有漏洞(一個有效配對日也能 PASS、缺漏可被排除後 PASS、沒有遠端回條也能進主樣本、提示詞指紋沒有真的檢查、120 日上限只在有買點的日子檢查、日曆只到 2027-02、出場不是完整可重播)。v2 已經有正式資料(10/14 的 12 筆),所以照 v2 自己的承諾:**改規則 = 開 v3、從新的日期收案;v2 的資料保留、答案不改、分開報**
- **v2 的定位(從現在起)**:照常每天收集、照常在它自己的時間做那一次分析,但**只當描述**,不能當「盤感有判斷力」或「網站只亮同意」的依據(Astra v0.7.2 §四.3)
- **v3 的做法**:每天的收集**完全不改**(`scripts/astra_ledger.py` v2 的 prep / lock / score、`prompt_v2.md`、268 檔名單、排程、模型都照舊);v3 是加在上面的一層「更嚴的收案 + 唯一一次分析」(`v3_verify.py`),只讀 git 物件,不寫 astra-ledger 分支、不碰排程
- **凍結與開始**:Astra 審過、使用者同意後,把這份(改名 `PROTOCOL_v3.md`)、`v3_verify.py`、模擬結果和下面 §8 的指紋一起 commit;**v3 的第一天 = 這個凍結 commit 被 GitHub 收到之後,第一個做 prep 的交易日**。凍結之後任何改動 = v4、新日期

## 1. 收案(每一筆買點都要全部成立,否則只列在「不收」的原因統計)
1. 不是試跑、`protocol = v2` 的收集、日期在 v3 收案期內、是官方交易日
2. **遠端回條已驗證**:`receipts/<asof>.json` 有 `run_id`、`verified = true`;回條的時間 < **官方日曆**算出的截止(下一個交易日 09:30 美東)。v2 帳上的截止和官方日曆不同時只記錄,判定一律用官方日曆
3. **鎖定 commit 的內容對得上**:在 `lock_commit` 那個 commit 裡,`verdicts/<asof>.json`、`pending/<asof>.json`、`engine_manifest.json` 的 SHA-256 = 這筆紀錄寫的;`marks.jsonl` 裡這一列和現在完全一樣;判讀檔裡這筆的同意 / 不同意和模型 = 紀錄;`snap/<asof>/<sym>.json.gz` 的 1,250 根 = `bars_sha256`
4. **凍結檔沒變**:鎖定 commit 裡的 `engine_manifest.json` = v3 凍結時記下的那一份;`prompt_v2.md`、`PROTOCOL.md`(v2)、`universe.txt` 的 SHA-256 = manifest 裡的(v2 程式沒有查提示詞,v3 查);main 上三支引擎在凍結之後沒有被改過(改過 → 改動之後的買點都不收)
5. **模型** = `claude-opus-5-5`(排程設定的模型 ID);其他模型的筆另列、不進主判定
- 一次性核對(2026-10-16):排程本身的提示詞(帳號 API 讀出)和 `prompt_v2.md` **逐位元相同**,SHA-256 `1bfc25e3…` = manifest 的 `prompt_sha256`。這只有帳號擁有者看得到,外人無法獨立核對(限制)

## 2. 收案期
- **固定 120 個官方交易日**(v3 第一天算第 1 天;零買點、失敗、沒跑的日子都算);不看筆數提早截止
- 為什麼不像 v2 收到 300 筆就停:模擬(`sim_power_block.py`)顯示約 25 天的收案期,區間嚴重偏窄(沒有判斷力時,5 日區塊的假陽性 6%,固定偏好某些股票時約 2 成「沒蓋到真值」)
- 官方日曆:NYSE Group 2025-12-23 公告的 2026 / 2027 / 2028 休市日(`v3_verify.py` `HOLIDAYS`);日曆用完(2028-12-29 之後)程式會停,要先補表(= 新版本)

## 3. 結果
- 出場照網站賣法(個股乙:頂 / 收盤 ≤ 進場 × 0.92 / 第 20 根;SPY、QQQ 丙:頂 / 第 40 根),隔天開盤;每邊扣 0.1%
- **正式結果 = v2 帳上記的出場,而且要能逐位重播**:用判讀時的快照(≤ 訊號日的 1,250 根)接上 `bars_used` 裡訊號日之後的 K 線,以凍結的 `sw_series` / `exit_of` 重算 → 進場日、出場日、出場原因、扣成本報酬都要一樣(報酬差 < 1e-12)。重播不出來(K 線不夠、結果不同)= **不可重現**
- 出場之後超過 5 個交易日才記錄 = 標「晚記錄」(照收,但另外報)
- 收案期結束後 41 + 10 個交易日還沒有結果 = **缺漏**

## 4. 判定(只做一次;`v3_look.json` 存在就不再做)
- **時間**:收案期最後一天之後 ≥ 41 個交易日,而且每一筆都有結果、或已被分到缺漏 / 不可重現
- **先過門檻,沒過 = 資訊不足(不判通過或不通過)**
  - 已結束且可重現 ≥ 300;同意 ≥ 60;不同意 ≥ 60
  - **有配對的日期 ≥ 80**(同一天、同一類型、兩邊都有判讀的日子;模擬:120 天的收案期中位數約 108 天、最差 1 成約 94 天)
  - 缺漏 + 不可重現 ≤ 3%
- **H1(主效果)**:同一天、同一類型的格子內「同意平均 − 不同意平均」,再對所有格子平均(和 v2 一樣,格子等權)
  - **下界 = min(日期 5 日移動區塊重抽的 2.5 百分位, 以股票為單位的 Poisson 重抽的 2.5 百分位)**,各 2,000 次、seed 20261016;**下界 > 0** 才成立
  - 為什麼兩個取小的:模擬(`sim2_cluster.py`,沒有判斷力的兩種貼法)— 只用日期 5 日區塊,假陽性 4.0%(隨機)/ 7.0%(固定偏好某些股票);兩個取小的 2.0% / 3.7%(120 天;目標 2.5%;300 個模擬視窗的誤差約 ±0.9 個百分點,「偏好某些股票」那一種仍略高)
- **H2**:同意組勝率 − 全部點勝率 ≥ 10 個百分點(未四捨五入)
- **缺漏的最壞情境**:缺的同意 = 全部已結束報酬的第 5 百分位;缺的不同意 = 第 95 百分位(不是一律 −100%,也不是刪掉)。**H1、H2 在「排除缺漏」和「最壞情境」兩種算法都要成立**
- **PASS(盤感有判斷力)** = 門檻都過 + H1 + H2(兩種算法)
- **上線候選(網站只亮 Claude 同意的買)** = PASS + **H3**:同意組本身扣成本平均的下界 > 0(同樣兩種重抽取小)+ 用固定判讀重播「一次一筆、只亮同意」的持倉路徑 + 使用者同意
- 判定前只顯示筆數、收案 / 不收原因、持有 / 結束 / 缺漏,不顯示勝率

## 5. 功效(先講清楚能看出多大的差)
- 模擬(266 檔歷史買點、2016 起的視窗、平移模型;`sim2_cluster.py`)— 「每一筆同意比不同意多 δ 個百分點」時,下界 > 0 的機率:

| 收案期 | δ = 0.5 | 1 | 1.5 | 2 | 3 |
|---|---:|---:|---:|---:|---:|
| 60 天 | 6% | 18% | 37% | 56% | 78% |
| **120 天(本草案)** | 9% | 27% | 53% | 74% | 90% |
| 250 天(約 1 年) | 20% | 50% | 73% | 83% | 91% |

- 白話:120 天大約只能抓到「每筆差 2 個百分點以上」的判斷力;差 1 個百分點的,四次有三次看不出來。H2 另外要勝率差 10 個百分點,實際功效比表上低
- 這是規劃用的近似:歷史買點、沒有判斷力的貼法、整體平移;真實判讀可能有別的相關結構

## 6. 已知限制
- 提示詞要模型判「會賺的機會比平常高」,H1 卻比平均報酬:兩者不同(較常小賺、偶爾大賠的點也可能被同意)。v3 **不改提示詞**(改了要動排程,是使用者的決定;改了也要新版本、新日期)。H1 和 H2 都要成立,所以不會只靠其中一個過關
- 模型 ID 是判讀檔自己寫的;排程提示詞只有帳號擁有者看得到;遠端回條是「GitHub 至遲已持有這個 commit」的證據,不是推論當下看了什麼的證明
- 事件研究,不是一到兩檔的帳戶績效;同一檔股票持有中再出現的買點也各算一次
- v2 和 v3 會重疊(v3 收案期內的筆,v2 也會收);兩者分開報,v2 只描述

## 7. 和 Astra v0.7.2 附錄五逐項對照
