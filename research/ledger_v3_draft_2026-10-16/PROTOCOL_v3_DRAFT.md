## 1. 要回答的問題(估計對象)
- **對象**:這 268 檔(266 股 + SPY、QQQ)在**未來日期**出現的網站「買」點;不是別的股票、不是帳戶績效
- **H1 的定義**:每個「(訊號日, 類型)」格子(類型 = 個股 stock / 指數 idx,**不是**底 / 回)裡「同意的平均報酬 − 不同意的平均報酬」(每邊扣 0.1%),只用兩邊都有的格子,再對**格子等權**平均。不是每筆交易等權,也不是帳戶報酬
  - 例:同一天個股格 100 同意 / 100 不同意差 +1 點,指數格各 1 筆差 −1 點 → H1 = 0;按交易數加權約 +0.98。兩者是不同的問題,結論一律用 H1 的名稱
- **推論**:「日期區塊 × 發行人」同時重抽(雙軸 Poisson / 區塊權重相乘,方向參考 Owen & Eckles 2012):每次重抽,完整收案日曆上長度 L 的移動區塊決定每天被抽幾次,每個發行人(GOOG、GOOGL 算同一家)另外抽一個 Poisson(1) 權重,每筆權重 = 兩者相乘;2,000 次、seed 20261016;下界 = 2.5 百分位
  - L 用事先寫好的規則從 {5, 10, 20} 選(`sim3_full.py`):**L = 5**(合成資料三種沒有判斷力的貼法、120 天、各 300 個視窗,H1 下界 > 0 都是 0 / 300)
  - 草案 1 的「兩個下界取小」不再當判定(Astra:那是交集條件,不是同時處理兩種相關的證明)

## 4. 結果(出場重播)
- 引擎從凍結 commit 的 **git 物件**取出、核對 SHA-256 後才載入;結果寫明實際執行的檔案指紋
- 之後的 K 線 = v2 帳上 `bars_used` 裡訊號日之後的部分,必須:第一根 = 下一個官方交易日、之後**一天都不少**、欄位合理(開高低收 > 0、低 ≤ 開 / 收 ≤ 高)
- 快照和 bars_used 尺度不同(資料商配息 / 分割重新還原)→ 快照整段乘同一比例對齊後再重播
- 用凍結程式重算的進場日、出場日、出場原因、扣成本報酬,和帳上一樣(報酬差 < 1e-12)= **在指定容忍度內重現**;不一樣、K 線不夠、或帳上記錄時間早於出場那根收盤 = **不可重現**
- 出場後超過 5 個交易日才記錄 → 標「晚記錄」(另報)
- 收案期結束後 41 + 10 個交易日還沒有結果 → 缺漏
- 限制:之後的 K 線來自 v2 結案時抓的那一次(不是每天另存);這回答的是「固定規則的事件研究」,不是「每天線上程式實際看到了什麼」

## 5. 判定(只做一次)
- **時間**:收案期最後一天之後 ≥ 41 個交易日,而且每一筆都有結果、或已分到缺漏 / 不可重現
- **門檻(沒過 = 資訊不足)**:已結束 ≥ 300、同意 ≥ 60、不同意 ≥ 60;有配對的日期 ≥ 80(候選下限,不是「80 次獨立行情」);同意、不同意各至少 30 家發行人;批次覆蓋 ≥ 90%;**沒有缺漏的不同意**;有效重抽 ≥ 90%
- **缺漏**:缺的「同意」一律用 **−100%**(做多 1 倍可能的最壞結果);缺的「不同意」報酬沒有有限上界 → 只要有就**資訊不足**。q05 / q95 補值改名「**壓力情境**」,只描述;另報「缺漏值要到多少結論才會翻」。不可重現也算缺漏(不能假設隨機)
- **H1**:§1 的格子平均差,雙軸重抽下界 > 0;「排除缺漏」和「缺的同意 = −100%」兩種都要成立
- **H2(待使用者決定,三選一)**:
  - 甲 原樣:同意勝率 − 全部勝率 ≥ 10 個百分點。注意:= (1 − 同意比例) × (同意勝率 − 不同意勝率);一半同意時要贏不同意 20 點,同意超過九成時不可能達成
  - 乙(建議):同意勝率 − 不同意勝率,雙軸重抽下界 > 0
  - 丙 不要 H2(勝率只描述)
- **PASS(盤感有判斷力)** = 門檻 + H1 + H2(兩種缺漏算法都成立)
- **上線候選(網站只亮同意)** = PASS + H3(同意組本身扣成本平均的下界 > 0)+ 用固定判讀重播「一次一筆、只亮同意」的持倉路徑 + 使用者同意
- 判定前只顯示筆數、收案原因、覆蓋、持有 / 結束 / 缺漏;不顯示勝率
- **唯一一次**:判定綁在實驗 ID,寫到固定位置 `research/ledger_v3/looks/<實驗 ID>.json`;工作區或 git 歷史(所有分支)有這個檔就不再做;試跑一定要 `--dry-run`,輸出標「不是正式結果」,不能寫進這個位置
