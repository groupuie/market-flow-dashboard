## 0. 一句話

財報公布後的五個交易日,每天收盤問:「**明天開盤買,三天內會不會先漲一段(FL3)?**」給機率。主要比較 **有經驗記憶的 Claude(C)** 和 **沒有記憶的 Claude(B)**;再用 **隨機成熟記憶(C0)** 看是不是「挑對的卡」才有用。

## 2. 時間規則(每一筆資料都要有 available_at)

1. **available_at(財報)**= EDGAR 索引頁「Accepted」(美東)換 UTC(E3、E8:索引頁 = SGML 231 / 231)。**不用** submissions JSON 的 acceptanceDateTime(59 / 107 家多 4 / 5 小時)。另記 `issuer_first_public_time`(公司第一次公開的時間;沒有原文證據就填 unknown,不拿 Accepted 代替)。
2. **交易日曆** = NYSE 官方日曆(含休市與提早收盤日)。**close_time(D)** = D 的實際收盤:一般 16:00 ET,提早收盤日 13:00 ET。價格的 available_at = 當天 close_time。資料缺的交易日不能拿別天補。
3. **反應日 r** = 第一個 close_time 晚於 available_at 的交易日。
4. **決定時間** d_j = close_time(r+j),j = 0…4。可用的資料:available_at ≤ d_j;價格到 r+j 收盤為止。
5. **進場參考價** e = r+j 下一個交易日的開盤,取 §2b 同一條還原序列的值;准入要求那天的原始 open 存在、> 0、不是補值、不是「沒有交易」。這是答案的參考價,不是真的成交(沒有下單)。
6. 每筆資料另記 `first_seen_at`、`retrieved_at`、原檔 SHA-256(`data_provenance.md`)。

## 3. 答案 FL3_A60 v0.2(逐字定義)

- **名稱**:FL3_A60 v0.2「收盤確認、停損優先、隔天開盤參考價」。
- **輸入**:決定日 t(= r+j);e(§2.5);A = ATR60(t) = t−59 … t 共 60 根真實區間的簡單平均;TR_i = max(H_i, C_{i−1}) − min(L_i, C_{i−1})(所以要用到 C_{t−60})。價格用 §2b 的同一條還原序列。
- **規則**:依序看交易日曆上的 i = t+1、t+2、t+3:
  1. 若 L_i ≤ e − A → **y = 0**,結束(同一天先看低點:同日跌破又收高也算 0;日 K 看不出盤中先後,這是保守規則)
  2. 否則若 C_i ≥ e + A → **y = 1**,結束
  3. 三天都沒有 → **y = 0**
- **成熟**:close_time(t+3)。
- **這不是**「盤中先碰上界就算成功」的障礙定義。規則改了就換名字或版本號,不沿用 FL3_A60 v0.2。
- **缺資料**:照 §2b 准入;t+1 … t+3 中間下市 / 停牌 → `label_unresolved`(附原因);不用最後收盤假裝能成交。
- **列的來源**:事件(8-K 2.02)× d0–d4 × 當年名單,只套 §2b 准入;**不用** walk7 W1 的篩選(W1 要求之後 20 天都有量、收盤不變 ≤ 2%,等於用未來資料挑列)。
- **敏感度(只報告)**:FL3_A20、FL3_FIX2(固定 2% × e)。
- **次要結果(只報告,不檢定)**:3 / 10 天最大逆行、10 天內收盤低於 e 的天數、10 天報酬、被套(t+10 收盤 < e)、固定 5 日報酬減同日名單平均。這些和舊研究的 AUC 不能直接比。
- **開發期基準率**(E11:價格層 v0.2、§2b 准入、不用 W1;反應日仍是 walk8 的、答案在 2026-07-01 以前成熟):94,288 列計分,FL3_A60 = **23.38%**;d0 26.39%、d1 23.68%、d2 22.57%、d3 21.94%、d4 22.29%。舊數字(walk7 價格、W1 篩過)23.56%;共同的 83,584 列答案 0 筆不同。

  1. 同一列 C 拿到 m 張 → C0 也 m 張(m = 0 時 C0 的提示等於 B,照樣記錄)

## 5. 檢定(預先登記草案)

- **計分單位**:列(事件 × 天);每個事件最多 5 列。主要估計 = 計分列等權平均(只有每個事件的計分列數都一樣時,才等於事件等權);敏感度 = 事件等權。不計分的列照 §2b 原因公布。
- **精度**:所有組在計分前都放到同一個 0.01 格點:Claude 各組要求輸出兩位小數;多於兩位小數或 R、BLEND 的值,一律用「四捨五入、0.005 進位」(十進位 ROUND_HALF_UP)到兩位;原始輸出另存。不是數字或超出 0–1 → 同一子代理重問一次,再錯就記 `invalid`(不計分、公布件數)。BLEND 的未四捨五入值、R 的全精度值只當敏感度。四捨五入本身會改 Brier(例:p = 0.5049、y = 1,0.24512401 → 0.25),所以各組一定同一規格。
- **主要 H1**:D1 = (p_B − y)² − (p_C − y)²;**D1 > 0 = C 比較準**。雙尾 5%。**只有 D1 > 0 且顯著才算通過**;顯著但 D1 < 0 → 報「加卡後變差」,停止之後所有優越性主張。
- **H1b(固定順序第二步)**:只有 H1 通過才檢。D2 = (p_C0 − y)² − (p_C − y)²;D2 > 0 = C 比較準;雙尾 5%,同樣要 D2 > 0 且顯著。
  - 讀法:只過 H1 =「加卡流程有效」;H1 + H1b 都過 =「這個選卡政策有增量」;H1b 沒過 ≠ 兩者一樣。
- **次要家族**(只有 H1 通過才算確認性;否則全部標「探索」):S1 B vs A、S2 A vs R、S3 C vs R、S5 P1 vs C、S6 P1 vs R、S7 P1 vs BLEND,共 6 個,Holm 校正。S4 校準(5 格)只描述。
- **誤報控制**:主要家族(H1 → H1b)與次要家族**各自**控制在 5%;兩個家族合起來的「任何一個誤報」可能高於 5%,報告時照這個寫。
- **檢定方法:凍結前用模擬挑定**。候選:反應週為群的正負號翻轉、兩向群聚(日期 × 事件)t、日期層級翻轉。**接受標準**(看任何真實 B / C 結果之前定死):
  1. 虛無情境至少 5 種:事件群聚、日期群聚、反應週群聚(各群大小不一)、日期 × 事件兩向群聚、同公司跨季相關;強度取自開發資料(E1:同一事件 5 天的答案組內相關約 0.18;E4:日期群聚)
  2. 每種情境模擬 ≥ 10,000 次;**誤報率的單邊 95% 上界(p̂ + 1.645 × 標準誤)≤ 5%**,全部情境都要過
  3. 都過的方法裡選功效最高的;如果沒有方法通過,在最保守的情境下用模擬把臨界值校準到 5%,再比功效
  4. 報告附每種情境的誤報率與模擬誤差
- **功效**:配對差 D = (p_B − p_C)(p_B + p_C − 2y)。同樣的機率差 RMS,平均改善可以是正、負或 0 → 要估的是 D 的變異和日期 / 事件之間的相關,不能只量 RMS。試做一輪只有 32 件、8 個日期、只做 d0 → **只能測流程、抽取品質、成本和 D 的粗略變異**;不能直接估整季 d0–d4 的相關結構,也不是有效性檢定。季數用 E4 的相關情境給範圍,不承諾。
- **最小有用效果** δ_min = 0.005(約基準 Brier 0.17 的 3%)。
- **H 只當關卡,F 才是確認**:保留季 H(半新)只決定要不要進 F(停止規則),**不算確認性檢定**。F 的季數 N 凍結時定死,N 季結束後做一次確認性檢定;中間每季可以公布數字,但不檢定、不因此改規則或提早宣稱。F 的結果要標證據等級(§7)。
- **停止規則**(H 結束後;區間 = 用主檢定方法反推的 80% 區間):
  1. D1 的 80% 區間上限 < 0.005 → 記憶這條線先停
  2. D1 點估計 ≥ 0.005 → 進 F
  3. 其他 → 只有點估計 > 0 才進 F,否則停
- **實用層**(只報告):每個事件取第一個「現在買」的那天,報 FL3、10 天最大逆行、10 天報酬、被套比例;比 B、C、C0、「R 機率前 20% 才買」、「d0 一律買」。

## 6. 功效與成本

- 一季 ≈ 446 個事件(2017–2026 中位)× 5 天 ≈ 2,230 列;最忙的 10 天佔一季的 68.5%(E1)。
- 季數規劃表(E4;理想檢定的散布,只當範圍;試做後用 §5 挑定的方法重算):

| B、C 機率差(RMS) | 看出 0.002 | 看出 0.005 | 看出 0.01 |
|---|---|---|---|
| 0.02 | 1.1 季 | 0.2 季 | — |
| 0.05 | 6.9 季 | 1.1 季 | 0.3 季 |
| 0.10 | 29.6 季 | 4.7 季 | 1.2 季 |

- **成本要先算平台開銷**(實測 2026-10-23):在這個環境,每個判讀都要開一個 Claude 子代理;一個「只回答 OK」的子代理就用了 **59,416 tokens**(系統提示與工具說明約 3 萬,回報結果要第二回合,再送一次)。每多 P tokens 的資料包,約再加 2P。v0.1 的「每次 4k–8k」沒有算這一塊。
- **試做一輪**(`trial_cost_manifest.json`;中估計,括號是低–高,都含 10% 重試):

| 做法 | 判讀 | 抽取 | 寫卡 | 合計 |
|---|---|---|---|---|
| 完整版、每列一個子代理 | 約 1,140 萬 | 約 580 萬 | 約 200 萬 | **約 2,110 萬**(1,950–2,390 萬) |
| 完整版、同組 8 列一批 | 約 310 萬 | 約 580 萬 | 約 200 萬 | **約 1,200 萬**(1,030–1,480 萬) |
| 省錢版(起始卡不抽財報)、8 列一批 | 約 310 萬 | 約 80 萬 | 約 100 萬 | **約 530 萬**(460–630 萬) |

  - 抽取以每個子代理 8 份新聞稿估(EX-99.1 中位約 2.5 萬字元、第 90 百分位約 4.8 萬;E3 的 80 份)。省錢版的 C 拿到的卡沒有「指引上調 / 下調」標籤,和正式設計的 C 不完全一樣。
  - 可能更便宜的做法:自訂一個沒有工具的判讀子代理,固定開銷也許小很多 —— 要先開一個實測(約數萬 tokens)才知道。
  - 到上限的處理:依事件一組一組做(同一事件的 A、B、C、C0、P1 做完才換下一個);用到所選版本中估計的 80% 先停下來回報;到高估計一定停,只用做完的事件。
- **整季**(之後才決定;中估計、含重試):全部五組、8 列一批 ≈ **2.5 億 tokens / 季**;每列一個子代理 ≈ 8.9 億;**縮小版**(成交金額前 150 檔、只做 d0 與 d2、只做 B / C / C0)≈ 2,300 萬 / 季。起始記憶 1,800 張另約 6,900 萬(一次)。
  - 結論:照原設計做整季在這個環境不可行;試做一輪的目的之一就是量出實際成本,再決定縮小到什麼範圍(縮小後季數會變多,要用 §5 的方法重算)。
