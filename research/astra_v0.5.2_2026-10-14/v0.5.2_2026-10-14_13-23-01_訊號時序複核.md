## 三、對 E1 下一輪四項建議的回覆

1. **接受明定訊號取位數。** 精確採發布函式 `round(x, 3) if abs(x) >= 1 else round(x, 5)`，是 Python 的二進位浮點 `round`，不能替換成 JavaScript `Math.round` 或十進位 half-up。▲底、△回、▼頂及其價格指標使用取位數副本；成交、ATR、估值使用未取位數的 Yahoo 還原 OHLC。
2. **接受績效前留存行情指紋。** 同時保存下載時間、日曆與程式指紋。再次下載另存一份；報訊號日期、交易序列及帳戶差異，保留第一次資料。
3. **接受 H64 描述對照。** 買點相同，不看頂、不看低點，一律 t+64 開盤清倉；即使沒有首頂也不改成 t+41。用來觀察單純持有較久的結果，不能把勝出的對照換成原先 E1 的主通過結果。
4. **接受縮小 E1 部位的描述，但修正「同曝險」名稱。** 用兩個平均曝險的比值當 w，再把 E1 初始資金縮為 w，實際曝險通常不會剛好相同。必須逐日重新計算資產、曝險與回撤，並公布匹配殘差。

這輪新增兩個明確界線：E1 尾段「跌破前 10 根最低收盤」在主規格維持舊實作的未取位數還原收盤；「所有價格觸發都取位數」另列敏感度。全歷史研究不能直接用只保留最近 1,250 根的 `website_snapshot`；取位數方式一致，不代表暖機和歷史視窗也相同。

### 3.1 為何 0.77 倍不等於同曝險

若期初投入 w，其餘持現，E1 部位自行複利，應使用：`總資產=(1−w)+w×E1資產`，`持股市值=w×E1持股市值`，再用兩者相除得到每天曝險。

例：E1 兩天都滿倉，資產由 1 漲到 2。只投入一半後，兩天曝險為 50% 和 66.67%，平均 58.33%，並不是 50%。因此要把 w、實際曝險和回撤一起報，不能直接把原回撤或 CAGR 乘 w。用整個 B 期結果求 w 再比較 B 期，只是事後描述。

### 3.2 用前段定部位時，還要剔除跨到後段的交易

本輪查到舊 ADI A 帳戶的起訖為 `2010-01-04 → 2018-04-04`。因為 A 是按訊號年分分類，2017 年底的買點仍持有到 2018 年。**不能把這份 A 帳戶拿來決定 2018 年一開始就要知道的 w。**

若日後加入 A→B 的固定配置對照，校準資料最晚只能到 2017 年最後交易日，只納入 `t+64` 也不晚於該日的完整窗口，並在首次讀取 B 期績效前凍結 w。不能因名稱寫 A 就忽略實際持有終點。

主比較仍只有 NEW_ALL、B 期、E1 對 B0，沿用 v0.5.1 的候選門檻：有限資本組合的 CAGR／MDD／Calmar，以及配對窗口增量；126 日日期區塊、2,000 次、seed 20261014、95% 區間；成本 0 與每邊 10 bp。主名單仍是字面三來源減去舊名單的 345 個 ticker，並須完成發行人與資料覆蓋核對。**345 檔目前是名單與設計，尚未執行績效**；Claude v1.9 的「E1 驗證已經用了 345 檔」應改成「E1 設計預定使用 345 檔」。附錄五包含全部設計細節。

### 4.1 找到一個實際的事件時間例子

IBM 2026 第二季的 API 資料列 `reportedDate=2026-07-22`，實際 EPS 與預估 EPS 都是 2.93，驚喜為零。可是 IBM 在 **7 月 14 日**就已公布初步 non-GAAP EPS 2.93。[IBM 7 月 14 日公告](https://newsroom.ibm.com/2026-07-14-Arvind-Krishnas-Letter-to-IBM-Investors)、[官方 EARNINGS demo](https://www.alphavantage.co/query?function=EARNINGS&symbol=IBM&apikey=demo)

若研究市場「第一次知道業績」之後的走勢，7 月 14 日才是必須處理的事件；如果研究正式 7 月 22 日公布，當時的零驚喜可能有意義。不能把 7 月 22 日的預估 2.93 回填成 7 月 14 日公告前的市場共識。這個例子不證明供應商錯誤，但證明只用單一 `reportedDate` 不夠。

SEC `acceptanceDateTime` 可作保守的文件可用時間，不能直接當財報最早發稿時間；8-K 可能較公司公告晚交。同季預告、正式公告與修訂都需配對。即使校正了實際 EPS 的公布時間，也還沒有證明歷史分析師共識當時可用。[SEC Form 8-K](https://www.sec.gov/files/form8-k.pdf)

### 4.2 我建議的研究順序

先核對 `EARNINGS` 的共識截點、事件類型、EPS 口徑與分割單位，再把財報驚喜與底／頂訊號合併研究。「7／30／60／90 天預估修正」先列待查，直到其歷史基準日與修訂規則有可引用的定義或當時保存快照。

可候選採用 `UE=actual−consensus`；SUE 的分母用**先前已公布八季** UE 的樣本標準差，不含當季。這是待登記的一種版本，不是唯一 SUE 定義。EPS 除以前一日股價時，兩者要同幣別、同分割基準；不能直接把含現金股利回溯調整的價格當成 EPS 的每股基準。缺共識、零分析師、基準不明、標準差為零或精度不足，均應預先列排除規則。詳見附錄四。

這些欄位是財報資訊，不會直接告訴我們機構真實淨買賣。選擇權 Gamma 加未平倉量也仍需持倉方向假設，不能因取得資料就把它稱作已觀測到的做市商淨曝險。

## 附錄一 六日與原帳戶核對程式

```python
"""Read-only replay of Claude v1.8's six dates against Astra's frozen snapshot.

No downloads, no new universe, no overwrite of the original experiment.
Usage: python3 verify_original_ties.py --study ../astra-exits-20261013 --output tie-audit.json
"""
import argparse
import datetime as dt
import gzip
import hashlib
import importlib.util
import json
from pathlib import Path
from zoneinfo import ZoneInfo

CASES = [
    ('ADI','2018-11-09','top',False),
    ('ADI','2018-11-12','top',True),
    ('ADI','2018-12-11','bot',False),
    ('PWR','2018-10-18','top',False),
    ('PWR','2021-11-05','bot',False),
    ('PWR','2021-11-08','bot',True),
]
EXPECTED_CALENDAR = '99be666ac4b579dae46f7e8b882f0eaac5b760beae83018a89832a5bdfaa0607'
EXPECTED_MANIFEST = 'a5cfada0b67deec9de6cf9a467c517e991609ff621ad3169dde5340256a56bf8'
EXPECTED_FREEZE = '3ef884394b836c39f43bbef7ebd16aa7900a541fb9c7fcdd5fecb6f16c254fe6'

def sha(data):
    return hashlib.sha256(data).hexdigest()

def load_module(name, path):
    spec = importlib.util.spec_from_file_location(name, path)
    module = importlib.util.module_from_spec(spec)
    spec.loader.exec_module(module)
    return module

def rounded(bars):
    # Match the pinned Python publisher's rp(), NOT Math.round or Decimal half-up.
    return [[b[0], *[round(x, 3) if abs(x) >= 1 else round(x, 5) for x in b[1:5]], b[5]] for b in bars]

def run(study):
    study = Path(study).resolve()
    if sha((study/'freeze.json').read_bytes()) != EXPECTED_FREEZE:
        raise ValueError('This is not the pinned original freeze.json')
    if sha((study/'data/manifest.json').read_bytes()) != EXPECTED_MANIFEST:
        raise ValueError('This is not the pinned original data snapshot')
    freeze = json.loads((study/'freeze.json').read_text())
    for name, expected in freeze['files'].items():
        if sha((study/name).read_bytes()) != expected:
            raise ValueError('Frozen source mismatch: '+name)
    data_tools = load_module('frozen_dt', study/'data_tools.py')
    experiment = load_module('frozen_ex', study/'experiment.py')
    data = study/'data'
    manifest = json.loads((data/'manifest.json').read_text())
    calbytes = (data/manifest['calendarFile']).read_bytes()
    assert sha(calbytes) == manifest['calendarSha256']
    calendar = json.loads(calbytes)['dates']
    calhash = sha(json.dumps(calendar,ensure_ascii=True,separators=(',',':'),allow_nan=False).encode())
    assert calhash == EXPECTED_CALENDAR
    original_accounts = json.loads((study/'evidence/accounts.json').read_text())
    rows, sources, account_results, changes = [], {}, [], {}
    for symbol in ('ADI','PWR'):
        entry = manifest['symbols'][symbol]
        blob = (data/entry['adjustedFile']).read_bytes()
        assert sha(blob) == entry['adjustedSha256']
        obj = json.loads(blob)
        rawzip = (data/obj['provenance']['rawFile']).read_bytes()
        raw = gzip.decompress(rawzip)
        assert sha(raw) == entry['rawSha256']
        assert sha(rawzip) == obj['provenance']['rawGzipSha256']
        yahoo = json.loads(raw)['chart']['result'][0]
        quote = yahoo['indicators']['quote'][0]
        zone = ZoneInfo(yahoo['meta']['exchangeTimezoneName'])
        rd = {dt.datetime.fromtimestamp(t,zone).date().isoformat():i for i,t in enumerate(yahoo['timestamp'])}
        bars = obj['bars']; rb = rounded(bars)
        dates = [b[0] for b in bars]; idx = {d:i for i,d in enumerate(dates)}
        assert dates == calendar  # These two complete histories need no gap approximation.
        un = data_tools.signals(bars)
        ro = data_tools.signal_source()(rb)
        sources[symbol] = {'adjustedSha256':sha(blob),'rawSha256':sha(raw),'bars':len(bars)}
        changes[symbol] = {kind:{'onlyUnrounded':[dates[i] for i in sorted(set(un[kind])-set(ro[kind]))],
                                'onlyRounded':[dates[i] for i in sorted(set(ro[kind])-set(un[kind]))]}
```

##### 不能從季度日期推定「N 天前」

這次 `EARNINGS_ESTIMATES` 有 `date=2027-12-31` 的未來年度列，同時已有 `eps_estimate_average_7_days_ago=13.1477` 等值。**因此 `date` 不能一律當作所有列的歷史快照基準日。** 它至少表示預估所屬期間；已公布季度的欄位究竟凍結在季末、財報日、供應商更新日或其他時點，公開文件沒有回答。

#### 2. 新發現：IBM 本身就有「先預告，再正式公布」

本輪 demo 的 IBM 2026-06-30 季顯示：`reportedDate=2026-07-22`、實際 EPS `2.93`、預估 EPS `2.93`、驚喜 `0`。[本輪 demo 來源](https://www.alphavantage.co/query?function=EARNINGS&symbol=IBM&apikey=demo)

但 IBM **7 月 14 日**的官方投資人信已披露初步第二季數字：GAAP EPS `2.27`、operating non-GAAP EPS `2.93`。該份 8-K 包含 Item 2.02，SEC 頁面 Accepted 顯示 `2026-07-14 07:01:52`。[IBM 官方公告](https://newsroom.ibm.com/2026-07-14-Arvind-Krishnas-Letter-to-IBM-Investors)、[SEC 提交紀錄](https://www.sec.gov/Archives/edgar/data/51143/000005114326000070/0000051143-26-000070-index.htm)、[SEC 公告附件](https://www.sec.gov/Archives/edgar/data/51143/000005114326000070/ibm-20260714xex991.htm)

**影響：**若研究的是「市場第一次知道業績後的漂移」，只用 API 的 7 月 22 日會錯過初步披露。若研究的是 7 月 22 日正式公布，相對當時最新共識的零驚喜可能有意義；兩者是不同事件，不可混成同一筆。**不能把 7 月 22 日這列的共識 2.93 回填成 7 月 14 日初步公布之前的預估。** 此例不能證明 Alpha Vantage 的共識數值有錯，但已證明單一季度 `reportedDate` 不足以標記全部重大財報資訊。

也不能把 SEC GAAP EPS 直接替換 API 的實際 EPS，再減掉其分析師預估。上述 `2.27` 與 `2.93` 口徑不同；必須核實每筆共識究竟對應 GAAP、調整後、持續營運、基本或稀釋 EPS。

#### 3. SEC 時間可作保守門檻，但不是原始發稿時間

Form 8-K 一般要求事件發生後四個工作日內提交；Item 2.02 處理已完成季度／年度結果的公開公告及其更新。因此 SEC 收件時間可能晚於公司發稿，且同一季度可以不止一份相關公告。不能把 `acceptanceDateTime` 直接命名為「財報發稿時間」。[SEC Form 8-K：General Instruction B、Item 2.02](https://www.sec.gov/info/edgar/forms/form8-k.pdf)

建議研究記錄三種時間：公司原始公告時間、EDGAR 收件／披露時間、資料供應商觀測時間；三者皆保留来源與原始字串。採 SEC 作保守可用門檻時，策略應在文件可取得後才形成訊號，並以匹配的附件 EPS 為準。API 更新有處理延遲，不宜假設收件當秒即可交易。[SEC API 更新說明](https://www.sec.gov/search-filings/edgar-application-programming-interfaces)

時區必須逐筆正規化，抽查 API 值和 SEC 原始 filing index／提交 header，採 `America/New_York` 的夏令時間規則；不能只用日曆日期判斷盤前盤後。此處提出的是驗證要求，**本輪沒有全面稽核 SEC API 時區是否一致**。

只把實際 EPS 的可用時間改成 SEC 時間，仍不能證明舊共識和「N 天前」值當時可用。若只有公布日期、沒有可信時段，主檢驗可預先定義為公告日期之後第一個完整交易日收盤才形成訊號、再隔日開盤成交；另報更早執行的敏感度，但不得事後選較好的版本。

#### 4. 分割、價格分母與 SUE

以下是 Astra 的研究建議，尚未採用績效選參數。

- **先對齊每股單位。** 實際 EPS、共識 EPS、過往驚喜、價格分母都要使用同一股數基準與幣別。NVIDIA 官方文件確認 2024 年十拆一，後續財報對歷史每股數字追溯調整；但這不能證明 Alpha Vantage 每個預估修訂欄位均同步調整。[NVIDIA 分割 FAQ](https://investor.nvidia.com/files/doc_downloads/2024/06/nvidia-2024-stock-split_faq_investors.pdf)、[NVIDIA 2024 年季度申報](https://www.sec.gov/Archives/edgar/data/1045810/000104581024000316/nvda-20241027.htm)
- **不能只見到數值約差十倍就自動除十。** 必須確認預估快照時點、分割生效日、供應商該欄位已調整範圍，避免重複調整。無法確認時標為不可用。
- **EPS 驚喜除以股價：** `SP=(actual-consensus)/P_before` 可避免預估 EPS 接近零造成比率暴增；但分母應是事件前、與 EPS 同一分割基準的價格。不要直接混用含現金股利回溯調整的 Yahoo Adjusted Close；報酬的還原價口徑與 EPS 的每股單位是不同問題。
- **候選 SUE：** `UE_q=actual_q-consensus_q`；`SUE_q=UE_q/std(UE_{q-8},...,UE_{q-1}, ddof=1)`。只用當時已公布的前八季，不把當季放進標準差；過往季 EPS 同樣要換成一致單位。這是本研究可登記的一個明確版本，不代表 SUE 只有此定義。
- **事先排除：** 缺共識、分析師數為零、口徑不明、分割無法對齊、過往有效季度不足八季、標準差為零或數值精度不足。缺值不能當零；SUE 不能恢復已被供應商四捨五入掉的資訊。
- 不以一個跨股票固定 EPS 門檻排除「太小數字」：未對齊分割會偏袒不同股數單位。先定義資料精度與有效位數條件，固定後才跑結果。

#### 2. 已核對：價格是 Python round，不是 JavaScript Math.round

固定來源 `1dbaddfcb1e75f772e550faa191a3ca9ea5834c8` 的 `scripts/astra_data.py`，SHA-256：

`506e35f1485b96bfc4795a1a339379b769d905d4fdaccbb27d33a9d331560e0a`

其發布價格函式為：

```python
def rp(x):
    return round(x, 3) if abs(x) >= 1 else round(x, 5)
```

發布流程先對 OHLC 使用 `rp`，再以這份發布資料跑 `sw_series`。`js_round(x) = floor(x + 0.5)` 確實也在檔案裡，但只用來顯示 RSI2 理由文字，**不是發布價格的取位數方式**。本輪取得的另一份 `claude-source/scripts/astra_data.py` 與上述固定檔案 SHA-256 相同。

Python `round` 對二進位浮點數的正好中點使用偶數取捨；不能替換成一般十進位「五入」、`Decimal` 的 half-up，或 `Math.round(x * 10**d) / 10**d`。用已釘住函式實測的例子：

| 輸入價格 | 位數 | 發布函式 rp | 正數 floor(x×10^d+0.5)/10^d |
|---|---:|---:|---:|
| 1.0625 | 3 | 1.062 | 1.063 |
| 0.015625 | 5 | 0.01562 | 0.01563 |

位數先由**未取位數**的價格決定。價格 0.999999 按五位得到 1.00000，不要因結果變成 1 再選一次位數。有效行情必須為正數；`abs` 不代表研究接受負價格。

建議下一輪採以下精確邊界：

1. 保存原始下載與未取位數還原行情，另建訊號輸入副本，只對其 OHLC 使用 `rp`；日期、成交量不變。
2. **▲底、△回、▼頂，以及 sw_series 裡全部由價格衍生的指標，使用這份取位數副本。** 不是只在最後一個 `>` 或 `<` 加 epsilon。嚴格突破仍為 `>`／`<`，相等不觸發，不另以原始未復權價格的相等覆寫判斷。
3. 買賣成交價、ATR、持倉估值使用**未取位數的 Yahoo 還原 OHLC**。這裡的「原價」不是未復權的 Yahoo quote 價格；混用兩者會把分割／配息口徑弄亂。
4. 為保留已選中的 E1 尾段政策，主規格的「收盤跌破前 10 根最低收盤」暫沿用舊 `episode` 的**未取位數還原收盤**。這一項與底／回／頂分開明列；若要將所有價格觸發一併取位數，應列成預定敏感度，不能默默把它算成只修底／頂的資料精度。
5. 未取位數敏感度採舊研究方式：完整歷史直接交給 `sw_series`，其他執行設定相同；另一項全觸發取位數敏感度，只改上述尾段低點條件，成交與估值仍不取位數。兩項結果完整呈現，不用較好者翻案。

#### 3. 交易時序：固定起點、終點與鎖資金時間

索引均以同一連續且有效的交易日行情為準；訊號日為 t，買入 e=t+1 開盤，共同終點 h=t+64 開盤。也就是從買入開盤至清倉開盤相隔 63 個交易日；不是「買入後再加 64 根」。

首頂 p 只搜尋 t+1 到 t+40（兩端都含）；出手日 x=p+1。不存在首頂時，B0、E1、E1a、E1b 都於 t+41 開盤全出。所有政策即使先賣完，也持現並鎖住該筆資金至 h；接受下一個訊號的條件為 `new_t >= previous_h`，新買進仍發生在其下一交易日開盤。不能為延長持有的策略放寬重疊借款，也不能讓 B0 提早再進場而宣稱是同一配對實驗。

有首頂時，定義低點觸發為 `C[j] < min(C[j-10:j])`；不含當日 close；在 j 收盤才知道，於 j+1 開盤成交。主規格此 C 的精度依第 2 節第 4 點。

|---|---|---|
| B0 | x 開盤全出 | x |
| E1（主候選） | x 開盤賣初始股數的一半；從 x 收盤起檢查低點，首次命中後次開盤賣餘部 | h |
| E1a（描述） | x 開盤不成交，只啟動和 E1 相同的尾段低點檢查；全倉等首次命中後次開盤 | h |
| E1b（描述） | x 開盤賣半；保留相同低點條件，餘部在低點後次開盤或 t+41 開盤較早者出清 | t+41 |
| H64（描述） | 首頂與低點都不觸發任何賣出；**即使沒有首頂也不提前出場** | h |

E1、E1a 最晚檢查到 h−1 收盤，命中後也是 h 開盤出場。E1b 的有效檢查到 t+40 收盤；若 x=t+41，在同一開盤直接全出即可。E1a 的啟動事件不生成零股交易或虛構費用。初始股數減半不是把剩餘資產的 50% 賣出。

每邊成本 10 bp 時，入場股數依含成本的可用資金算；每次賣出只按實際賣出金額扣成本。E1 比全出分兩次成交，不代表要對原始全額扣兩次退出成本。零成本與 10 bp 的所有政策使用相同訊號、相同窗口。

H64 能回答「機械式一直抱是否也有同方向效果」，但 E1 與 H64 同時差在首頂減半、無頂分支和尾段退出，不構成單一機制的因果估計。E1a、E1b 與 H64 都是固定的拆解描述，不挑最好的一組替代主規則。

#### 4. 同曝險：比例縮小不等於真的匹配

必須先選定曝險口徑。建議以有限資本**總組合**每天收盤的持股市值 G[d] 除以總資產 V[d]，再對同一日曆全部日子等權平均；沒有持股的日子填 0。不能把配對窗口曝險、股票平均、中位數或總組合曝險互換。原程式帳戶 `exposure` 是單一子帳戶的日均比率；把它的中位數相除，不會自動得到總組合的配比。

##### 4.1 B 期事後描述

Claude 的 `w = mean_exposure(B0) / mean_exposure(E1)` 可以保留成直觀描述。若禁止槓桿，用 `w = min(1, ratio)`；分母為 0 時填不可估，不能除以極小數。若原 E1 曝險比 B0 小，無槓桿縮小部位不能匹配 B0，必須直接標明未匹配。

把 E1 投入 w 倍後，不能直接把曝險、CAGR 或最大回撤乘 w。假設期初只把 w 放進 E1 的獨立資金部位、其餘持零利息現金，不再往兩者搬錢。完整 E1 曲線從 V[0]=1 開始，則：

```text
V_w[d] = (1 − w) + w × V_E1[d]
G_w[d] = w × G_E1[d]
Exposure_w[d] = G_w[d] / V_w[d]
```

以這條 V_w 逐日重算回撤、CAGR、Calmar，並報實際日均曝險與 B0 的差距。這與「每次重新拿當時總資產的 w 買進」是兩種策略，本設計採**期初配置一次、E1 部位自行複利、外部現金不動**。

反例：E1 在兩個觀測日的 V 與 G 都是 `[1, 2]`，原曝險皆 100%；B0 目標平均曝險 50%。按比例選 w=0.5 後，E1 日曝險是 50% 與 66.67%，平均 **58.33%**，並不是 50%。此算術已以程式核對。

若一定要稱「同曝險」描述，應在 `[0,1]` 求解 w，使變換後的**實際日均曝險**等於 B0；正資產、非負持股下這個函數隨 w 單調，可用固定精度二分法。仍須把所求 w、殘差與全部每日曲線公開。對以上反例，真正匹配的 w 是 `sqrt(2)−1≈0.414214`。

無論用比值或二分求解，若用 **B 期資料求 w 再評估 B 期**，都是事後匹配／描述。它有助理解風險來源，但不是交易者在 B 期起點已知道的配置，也不是新的樣本外成功。

##### 4.2 可預先固定的 A → B 配置對照

若要補上沒有使用 B 期資訊的對照，建議固定如下：

1. **校準用 A 期的觀測終點必須在 2017 年最後一個交易日（2017-12-29）以內**，只納入 `t+64 <= 2017-12-29` 的完整窗口，排除尾端尚未成熟訊號，所有曝險與資產觀測也在該日截止。舊研究的 A 期按「訊號年」分組，2017 年末訊號的 t+64 會延伸到 2018；**不能直接使用舊 A 帳戶曲線或帳戶摘要求 w_A**，否則會先讀到 B 期行情。按此新校準邊界重播 A 期有限資本曲線，較早結束後的空窗持現至統一截止日。
2. 用上述 A 期、成本 0、同一有限資本口徑，計算 B0 的日均曝險，並用前式在 E1 校準曲線求 w_A；搜尋區間 `[0,1]`，二分 60 次，無法匹配則固定為 1 並標明 A 期未匹配。若 E1 曝險為零，列不可估。
3. 把 w_A、校準起訖日、A 期目標與實際曝險、行情指紋及程式版本保存。**首次讀取 B 期績效前凍結**，不因 B 期表現調整。其行情與窗口觀測不跨過 2017 年末，才符合在 B 期第一個交易日之前決定配置的資料時序。
4. B 期開始只配置 w_A 進 E1 資金部位，餘額持現。B 期成本 0 與 10 bp 都沿用同一個 w_A，不各自重新最佳化；每天用實際資產重算。A 期匹配不代表 B 期也匹配，報出 B 的真實差距。
5. 這只是預定描述對照；主研究仍為完整 E1 對 B0。當代股票名單、現在下載的還原價、同年代市場與 E1 先前已被選中的限制仍在；A → B 固定 w 沒有消除這些偏誤，也不等於 2018 年實際已部署的策略。

不要按各股票在 B 期的結果各調一個 w，也不要同時試很多風險指標、持有期和 w 後只交最好者。
